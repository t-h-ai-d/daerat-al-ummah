# Deploy دائرة الأمة without Manus or Cloudflare

**Target stack:** Render Docker Web Service, Aiven MySQL, and Backblaze B2 private object storage. This uses the existing Node/Express deployment path—not Cloudflare Workers—and is independent of Manus and Cloudflare.

> This is a small-community MVP stack. Render’s free web service idles after 15 minutes, and Aiven’s free MySQL tier has 1 GB of storage and can power down after inactivity. It is not an always-on, high-traffic production architecture. [1] [2]

## 1. Accounts that must belong to you

Create or use accounts under your own email for GitHub, Render, Aiven, and Backblaze. These accounts—not Manus—will control the future site, database, and uploads.

| Provider | Purpose | What to create |
| --- | --- | --- |
| GitHub | Source-code recovery | The existing private `t-h-ai-d/daerat-al-ummah` repository |
| Render | Node/Express website | A Docker Web Service created from the repository Blueprint |
| Aiven | MySQL database | One free MySQL service in a nearby region |
| Backblaze | Avatar and attachment storage | One **private** B2 bucket named `daerat-media` |

## 2. Create the MySQL database in Aiven

In Aiven, create **MySQL** using its free plan and select a region close to your users. Aiven offers a standard MySQL service, automated backups, and no time-limited free plan; the free service is small and not high-availability. [2] [3]

On the service **Overview** page, copy the full connection string shown as the service URI. Do not share it in chat or commit it to GitHub. Create the application schema once from a local clone of the repository:

```bash
DATABASE_URL='PASTE_THE_AIVEN_SERVICE_URI_HERE' DATABASE_SSL=true pnpm db:push
```

If your database password has `@`, `:`, `/`, `?`, or `#`, use the complete Aiven URI rather than manually assembling a URL. The application’s new `DATABASE_SSL=true` setting makes the Node driver require TLS.

## 3. Create private object storage in Backblaze B2

Backblaze B2 supports the S3 API, so the existing upload adapter works without code changes. Its first 10 GB of storage is free, and the bucket must remain private because members’ media is served through the application’s signed download route. [4] [5]

Create a B2 bucket named `daerat-media`, keep it private, then create an application key restricted to that bucket with file read and write permission. Backblaze shows the bucket’s S3 endpoint, key ID, and application key immediately after creation. Save them in a password manager; the secret key cannot be displayed again.

| Render variable | Backblaze value |
| --- | --- |
| `S3_ENDPOINT` | The bucket’s S3-compatible endpoint, for example `https://s3.us-west-004.backblazeb2.com` |
| `S3_REGION` | The B2 region, for example `us-west-004` |
| `S3_BUCKET` | `daerat-media` |
| `S3_ACCESS_KEY_ID` | Backblaze key ID |
| `S3_SECRET_ACCESS_KEY` | Backblaze application key |
| `S3_FORCE_PATH_STYLE` | `false` |

## 4. Deploy on Render

Open Render, choose **New → Blueprint**, connect the private GitHub repository, and let Render read `render.yaml`. The Blueprint explicitly chooses `runtime: docker`, so Render runs the Node/Express server rather than misclassifying the Vite client as a static website. It creates `JWT_SECRET` automatically and asks for the values marked `sync: false`. [1] [6]

Enter the following Render values during Blueprint setup. Keep them as secret environment variables.

| Variable | Value |
| --- | --- |
| `NODE_ENV` | `production` |
| `JWT_SECRET` | Generated by the Blueprint; do not change it after members register |
| `DATABASE_URL` | The complete Aiven service URI |
| `DATABASE_SSL` | `true` |
| `S3_ENDPOINT` | Backblaze endpoint from section 3 |
| `S3_REGION` | Backblaze region from section 3 |
| `S3_BUCKET` | `daerat-media` |
| `S3_ACCESS_KEY_ID` | Backblaze key ID |
| `S3_SECRET_ACCESS_KEY` | Backblaze application key |
| `S3_FORCE_PATH_STYLE` | `false` |

After the first deploy, open the Render URL. Register a new test account, publish a text post, upload one harmless image, and sign out and back in. Remove the test account using the app’s account-deletion control when finished.

## 5. Recovery and ownership

The live site depends on the Render, Aiven, and Backblaze accounts. No free provider can keep a site online after its only owner deletes its account. Protect yourself by keeping the GitHub repository, B2 keys, and database exports outside Manus.

Export the database weekly from your own computer:

```bash
MYSQL_PWD='AIVEN_DATABASE_PASSWORD' mysqldump \
  --host='AIVEN_HOST' --port='AIVEN_PORT' --user='avnadmin' \
  --single-transaction --quick --routines --events --triggers 'defaultdb' \
  | gzip > "daerat-al-ummah-$(date -u +%F).sql.gz"
```

Store the encrypted `.sql.gz` export in two locations you control. Test restoring it into a new MySQL database before you depend on it.
