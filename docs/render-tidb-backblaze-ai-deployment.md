# تشغيل دائرة الأُمَّة باستقلالية: Render + TiDB Cloud + Backblaze B2

تُشغِّل هذه الخطة الموقع من حساباتك أنت: مستودع GitHub الخاص، وخدمة Render، وقاعدة TiDB Cloud المتوافقة مع MySQL، وتخزين Backblaze B2. لا يعتمد الموقع المنشور بهذه الطريقة على حساب Manus.

> **مهم:** لا يوجد استضافة مجانية مضمونة إلى الأبد أو بلا مخاطر إغلاق حساب. احتفظ بحساباتك، ونسخ احتياطية من قاعدة البيانات، ومفاتيح التخزين في مدير كلمات مرور مستقل.

## 1. TiDB Cloud

أنشئ مثيل **TiDB Cloud Starter أو Essential**، ثم افتح **Connect** وانسخ سلسلة الاتصال الخاصة بـ MySQL/Node.js. تتطلب هذه الخطط TLS للاتصال العام، ويمكن للعميل الذي يستخدم مخزن شهادات النظام الاتصال دون تنزيل شهادة خادم منفصلة.[^tidb-connect][^tidb-tls]

ضع في Render متغيّر البيئة التالي بسرية:

| المتغيّر | القيمة |
| --- | --- |
| `DATABASE_URL` | سلسلة الاتصال الكاملة المنسوخة من TiDB، مثل `mysql://USER:PASSWORD@HOST:4000/DATABASE?ssl-mode=REQUIRED` |
| `DATABASE_SSL` | `true` |
| `AUTO_DB_PUSH` | `true` عند النشر الأول لإنشاء الجداول الجديدة |

لا تكتب كلمة المرور في GitHub أو المحادثات. إذا كانت فيها رموز خاصة مثل `@` أو `#`، انسخ السلسلة التي ولّدتها TiDB كما هي بدل تركيبها يدويًّا. بعد نجاح الإطلاق الأول، راجع الجداول والتسجيل بحساب تجريبي ثم احذف الحساب التجريبي.

## 2. Backblaze B2

أنشئ bucket خاصًّا باسم تختاره، وأنشئ مفتاح تطبيق مقيدًا بهذا الـ bucket مع صلاحية قراءة وكتابة الملفات. أضف القيم التالية في Render:

| المتغيّر | القيمة |
| --- | --- |
| `S3_ENDPOINT` | نقطة S3 الخاصة بمنطقة B2 |
| `S3_REGION` | منطقة B2، مثل `us-west-004` |
| `S3_BUCKET` | اسم الـ bucket الخاص بك |
| `S3_ACCESS_KEY_ID` | Key ID من Backblaze |
| `S3_SECRET_ACCESS_KEY` | Application Key من Backblaze |
| `S3_FORCE_PATH_STYLE` | `false` |

إذا أُرسل Application Key في محادثة أو ظهر في سجل عام، ألغِه من Backblaze فورًا وأنشئ مفتاحًا جديدًا ثم بدّله في Render.

## 3. الفحص الآلي الحذر للسبام

طبقة الفحص الجديدة لا تُصدر فتوى ولا تحذف أو تعاقب تلقائيًّا. هي تفحص **نص المنشور فقط** بحثًا عن سبام واحتيال وخداع ومضايقة وإهانة دينية صريحة وأنماط استنزاف الانتباه الواضحة. أي منشور عالي الخطر يوضع **قيد مراجعة بشرية** مع رسالة واضحة لصاحبه. تبقى البلاغات متاحة فقط عبر البريد `ssbmbwuugame@gmail.com`، ولا توجد مساحة إشراف ظاهرة للأعضاء.

| المتغيّر | القيمة |
| --- | --- |
| `OPENAI_API_KEY` | مفتاح خادمي سري لمزوّد الفحص الآلي |

إن لم تضف `OPENAI_API_KEY`، تستمر قواعد السبام البسيطة داخل الخادم، لكن الفحص الدلالي بالذكاء الاصطناعي يتعطّل بأمان والمنشورات العادية تُنشر دون قرار آلي. لا تضع هذا المفتاح في أي متغيّر يبدأ بـ `VITE_` ولا في واجهة الموقع.

## 4. النشر على Render

من Render اختر **New → Blueprint**، واربط المستودع الخاص `t-h-ai-d/daerat-al-ummah`. يقرأ Render ملف `render.yaml`، وينشئ `JWT_SECRET`، ويطلب القيم السرية أعلاه. بعد إضافة المتغيرات، نفّذ **Manual Deploy → Deploy latest commit**.

سيشغّل الحاوي مخطط Drizzle الحالي عند وجود `AUTO_DB_PUSH=true`، بما في ذلك الجداول الخاصة بالمجتمعات والمجتمعات الفرعية وعضوياتها وفحص المنشورات. لا تغيّر `JWT_SECRET` بعد إنشاء حسابات الأعضاء، وإلا ستنتهي الجلسات الحالية.

## 5. فحص سريع بعد النشر

1. افتح رابط Render وسجّل حساب اختبار محليًا بالبريد واسم المستخدم وكلمة المرور.
2. تأكّد من أن الصفحة الرئيسية قابلة للتمرير دون تصغير، وأن حالة عدم وجود محتوى تعرض «الدَّائِرَةُ فارِغَةٌ».
3. أنشئ مجتمعًا ومجتمعًا فرعيًا، وانضم إليهما، وانشر نصًا مع رمز تعبيري أو GIF.
4. اضغط «إبلاغ» وتأكد أنه يفتح رسالة بريد إلى `ssbmbwuugame@gmail.com`.
5. انشر نص اختبار سبام واضح (ثلاثة روابط أو أكثر) للتأكد من أنه يظهر لصاحبه كـ «قيد مراجعة بشرية» بدلاً من اختفائه بصمت.
6. احذف حساب الاختبار أو بياناته بعد الانتهاء.

## 6. النسخ الاحتياطي والملكية

صدّر قاعدة TiDB دوريًا باستخدام بيانات اتصال TiDB المخزّنة لديك، واحفظ النسخة المضغوطة المشفرة في مكانين مستقلين. احتفظ أيضًا بنسخة من مستودع GitHub الخاص ومفاتيح B2 وRender. لا تحذف حساب Render أو TiDB أو Backblaze الذي يدير الموقع قبل نقل الخدمة ومفاتيحها إلى حساب آخر.
