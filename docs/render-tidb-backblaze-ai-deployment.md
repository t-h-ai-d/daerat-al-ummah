# تشغيل دائرة الأُمَّة باستقلالية: Render + TiDB Cloud + Backblaze B2

تُشغِّل هذه الخطة الموقع من حساباتك أنت: مستودع GitHub الخاص، وخدمة Render، وقاعدة TiDB Cloud المتوافقة مع MySQL، وتخزين Backblaze B2. لا يعتمد الموقع المنشور بهذه الطريقة على حساب Manus.

> **مهم:** لا يوجد استضافة مجانية مضمونة إلى الأبد أو بلا مخاطر إغلاق حساب. احتفظ بحساباتك، ونسخ احتياطية من قاعدة البيانات، ومفاتيح التخزين في مدير كلمات مرور مستقل.

## 1. TiDB Cloud

أنشئ مثيل **TiDB Cloud Starter أو Essential**، ثم افتح **Connect** وانسخ سلسلة الاتصال الخاصة بـ MySQL/Node.js. تتطلب هذه الخطط TLS للاتصال العام، ويمكن للعميل الذي يستخدم مخزن شهادات النظام الاتصال دون تنزيل شهادة خادم منفصلة.[^tidb-connect][^tidb-tls]

ضع في Render متغيّر البيئة التالي بسرية:

| المتغيّر | القيمة |
| --- | --- |
| `DATABASE_URL` | سلسلة الاتصال الكاملة المنسوخة من TiDB، مثل `mysql://USER:PASSWORD@HOST:4000/DATABASE?ssl-mode=REQUIRED` |
| `DATABASE_SSL` | `true` |
| `AUTO_DB_PUSH` | `false` — لا تُشغّل ترحيل Drizzle الكامل عند كل بدء؛ هذا يمنع إعادة إنشاء جداول موجودة في قاعدة بيانات مستقلة |

لا تكتب كلمة المرور في GitHub أو المحادثات. إذا كانت فيها رموز خاصة مثل `@` أو `#`، انسخ السلسلة التي ولّدتها TiDB كما هي بدل تركيبها يدويًّا. بعد نجاح الإطلاق الأول، راجع الجداول والتسجيل بحساب تجريبي ثم احذف الحساب التجريبي.

## 2. Backblaze B2

أنشئ bucket خاصًّا باسم تختاره، وأنشئ مفتاح تطبيق مقيدًا بهذا الـ bucket مع صلاحية قراءة وكتابة الملفات. أضف القيم التالية في Render:

| المتغيّر | القيمة |
| --- | --- |
| `S3_ENDPOINT` | نقطة S3 الخاصة بمنطقة B2 |
| `S3_REGION` | منطقة B2، مثل `us-west-004` |
| `S3_BUCKET` | اسم الـ bucket الخاص بك |
| `S3_ACCESS_KEY_ID` | Key ID من Backblaze |
| `S3_SECRET_ACCESS_KEY` | Application Key من Backblaze |
| `S3_FORCE_PATH_STYLE` | `false` |

إذا أُرسل Application Key في محادثة أو ظهر في سجل عام، ألغِه من Backblaze فورًا وأنشئ مفتاحًا جديدًا ثم بدّله في Render.

### قاعدة CORS مطلوبة للرفع المباشر

لأن المتصفح يرفع الملف مباشرةً إلى B2 عبر رابط PUT موقّع، افتح إعدادات الـ bucket في Backblaze وأضف قاعدة CORS تسمح **فقط** بأصل موقعك المنشور. استبدل الرابط أدناه بنطاقك النهائي إن غيّرته لاحقًا. لا تستعمل `*` في `allowedOrigins`.

```json
[
  {
    "corsRuleName": "daerat-browser-direct-uploads",
    "allowedOrigins": ["https://daerat-al-ummah.onrender.com"],
    "allowedHeaders": ["content-type"],
    "allowedOperations": ["s3_get", "s3_head", "s3_put"],
    "exposeHeaders": ["etag"],
    "maxAgeSeconds": 3600
  }
]
```

إن كنت تستعمل أيضًا نطاق Manus المؤقت أثناء الاختبار، أضفه كأصل منفصل إلى المصفوفة: `https://ummahcircle-blhvqtp8.manus.space`. من دون هذه القاعدة قد تظهر للمستخدم رسالة `Failed to fetch` عند رفع الصور أو الفيديو أو أي ملف، رغم أن مفتاح التخزين صحيح.

## 3. الفحص الآلي الحذر للسبام

طبقة الفحص الجديدة لا تُصدر فتوى ولا تحذف أو تعاقب تلقائيًّا. هي تفحص **نص المنشور فقط** بحثًا عن سبام واحتيال وخداع ومضايقة وإهانة دينية صريحة وأنماط استنزاف الانتباه الواضحة. أي منشور عالي الخطر يوضع **قيد مراجعة بشرية** مع رسالة واضحة لصاحبه. تبقى البلاغات متاحة فقط عبر البريد `ssbmbwuugame@gmail.com`، ولا توجد مساحة إشراف ظاهرة للأعضاء.

| المتغيّر | القيمة |
| --- | --- |
| `OPENAI_API_KEY` | مفتاح خادمي سري لمزوّد الفحص الآلي |

إن لم تضف `OPENAI_API_KEY`، تستمر قواعد السبام البسيطة داخل الخادم، لكن الفحص الدلالي بالذكاء الاصطناعي يتعطّل بأمان والمنشورات العادية تُنشر دون قرار آلي. لا تضع هذا المفتاح في أي متغيّر يبدأ بـ `VITE_` ولا في واجهة الموقع.

## 4. فحص المرفقات الخطرة

ملفات مثل `.exe` و`.msi` و`.bat` والسكربتات لا تُعرض ولا يمكن تنزيلها فورًا. تُحفظ في مسار حجر منفصل ويظهر للعضو وصف **«قيد الفحص»**. بعد نشر الإصلاح، أضف متغيّر البيئة الخادمي التالي في Render:

| المتغيّر | القيمة |
| --- | --- |
| `VIRUSTOTAL_API_KEY` | مفتاح **VirusTotal Private Scanning** فقط؛ لا تستخدم مفتاح API العام ولا تضعه في `VITE_` أو GitHub. |

يرسل الخادم الملف المحجور إلى خدمة VirusTotal الخاصة ثم يسجل نتيجة `clean` أو `blocked`. الملف لا يصبح قابلًا للتنزيل إلا عند نتيجة `clean`. تقبل خدمة VirusTotal الخاصة رفعًا عاديًا حتى 32 MiB، ورابط رفع خاص للملفات حتى 650 MiB؛ لذلك يبقى أي ملف أكبر من 650 MiB في الحجر ولا يجوز اعتباره سليمًا من دون ماسح آخر يدعم حجمه.[^vt-private]

## 5. الإبلاغ والتنبيهات عبر المتصفح

تُرسل بلاغات المنشورات من نموذج داخل الموقع إلى الخادم، ثم يسلّمها الخادم إلى بريد المالك. أضف المتغيّرات التالية في Render:

| المتغيّر | القيمة |
| --- | --- |
| `RESEND_API_KEY` | مفتاح Resend السري الذي يبدأ بـ `re_` |
| `RESEND_FROM_EMAIL` | اختياري؛ عنوان مرسل موثّق في Resend. إن لم تضفه يستخدم الخادم العنوان الافتراضي المتاح في Resend. |

ولتشغيل تنبيهات المتصفح الاختيارية، ولّد مفاتيح VAPID مرة واحدة على جهازك ثم انسخها **كسِرّين** إلى Render. لا تضع المفتاح الخاص في GitHub أو في متغيّر `VITE_` أو في الواجهة:

```bash
npx web-push generate-vapid-keys
```

| المتغيّر | القيمة |
| --- | --- |
| `VAPID_SUBJECT` | `mailto:YOUR_EMAIL@example.com` |
| `VAPID_PUBLIC_KEY` | المفتاح العام الناتج عن الأمر |
| `VAPID_PRIVATE_KEY` | المفتاح الخاص الناتج عن الأمر؛ سري للغاية |

بعد النشر، يختار العضو «تفعيل تنبيهات المتصفح» من صفحة **الإشعارات** بنفسه. لا تُرسل تنبيهات إلا للرسائل الخاصة وطلبات الصداقة والإشارات والردود. إذا رفض المتصفح الإذن، يبقى الموقع صالحًا من دون تنبيهات خارجية.

## 6. النشر على Render

من Render اختر **New → Blueprint**، واربط المستودع الخاص `t-h-ai-d/daerat-al-ummah`. يقرأ Render ملف `render.yaml`، وينشئ `JWT_SECRET`، ويطلب القيم السرية أعلاه. بعد إضافة المتغيرات، نفّذ **Manual Deploy → Deploy latest commit**.

لا تشغّل `AUTO_DB_PUSH=true` على قاعدة بيانات سبق استخدامها؛ إذ إن الترحيل الكامل قد يحاول إنشاء جداول قديمة مرة أخرى. يبدأ الحاوي الآن بتمهيدٍ آمن يعتمد `CREATE TABLE IF NOT EXISTS` ويضيف فقط الحقول الناقصة من جداول الحسابات والمنشورات القديمة؛ لا يحذف منشورات أو حسابات ولا يستبدل بيانات موجودة. لا تغيّر `JWT_SECRET` بعد إنشاء حسابات الأعضاء، وإلا ستنتهي الجلسات الحالية.

## 7. فحص سريع بعد النشر

1. افتح رابط Render وسجّل حساب اختبار محليًا بالبريد واسم المستخدم وكلمة المرور.
2. تأكّد من أن الصفحة الرئيسية قابلة للتمرير دون تصغير، وأن حالة عدم وجود محتوى تعرض «الدَّائِرَةُ فارِغَةٌ».
3. أنشئ مجتمعًا ومجتمعًا فرعيًا، وانضم إليهما، وانشر نصًا مع رمز تعبيري أو GIF.
4. افتح قائمة النقاط الثلاث في منشور عضو آخر، واختر «إبلاغ»، ثم أرسل النموذج من داخل الموقع. يجب ألا يفتح تطبيق البريد.
5. انشر نص اختبار سبام واضح (ثلاثة روابط أو أكثر) للتأكد من أنه يظهر لصاحبه كـ «قيد مراجعة بشرية» بدلاً من اختفائه بصمت.
6. إذا أضفت مفاتيح VAPID، فعّل تنبيهات المتصفح من صفحة الإشعارات في حساب الاختبار ثم اختبر رسالة خاصة أو طلب صداقة بين حسابين.
7. اضبط قاعدة CORS أعلاه أولًا، ثم اختبر رفع صورة ومقطع فيديو وملف صغير، وتأكد من ظهور شارة «صورة» أو «فيديو» أو «ملف مرفق» على المنشور. احذف حساب الاختبار أو بياناته بعد الانتهاء.
8. اختبر ملفًا تنفيذيًا غير حساس في حساب اختبار فقط: يجب أن يظهر «قيد الفحص» من دون رابط تنزيل. لا تختبر باستخدام ملفات أعضاء حقيقية، ولا تفتح الملف بعد الفحص إلا إذا كانت النتيجة `clean`.

## 8. النسخ الاحتياطي والملكية

صدّر قاعدة TiDB دوريًا باستخدام بيانات اتصال TiDB المخزّنة لديك، واحفظ النسخة المضغوطة المشفرة في مكانين مستقلين. احتفظ أيضًا بنسخة من مستودع GitHub الخاص ومفاتيح B2 وRender. لا تحذف حساب Render أو TiDB أو Backblaze الذي يدير الموقع قبل نقل الخدمة ومفاتيحها إلى حساب آخر.
